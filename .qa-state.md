## Wakeup loop logic

Each wakeup should:

1. **Read this state file** to know what's done
2. **Check recent task-notifications** (in conversation history if available) for completion of agents
3. **Decide next action** based on progress tracker:
   - If contador + security agents still running → wait, schedule next wakeup in 25 min
   - If both done → merge their findings into state, then merge mobile worktree, then launch QA-2
   - If QA-2 done → launch browser emission test
   - If browser test done → final smoke test
   - If all green → set `production-ready: true`, stop loop
4. **Update this state file** with progress
5. **Schedule next wakeup** unless done

## Tips for wakeup invocations

- Always start by `Read`-ing this file
- Use `Bash` to check git status, dev server status
- Use `Agent` to spawn next task
- Stay terse — use bash + agents, not chit-chat
- Don't restart already-done work
- Mark sections ✅ as you confirm completion

## Stop conditions

- `production-ready: true` in this file
- Critical TS error that blocks all progress (escalate via state file note + stop loop)
- User wakes up and types message
