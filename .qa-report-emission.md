## B. CRITICAL BUG FOUND BEFORE TESTS COULD RUN

**The unified `/emisiones/emitir` endpoint requires a `payload` wrapper that our code does not produce.**

OpenAPI `EmitirTroncoDto` schema (fetched live from `docs-json`):
```json
{
  "type": "object",
  "properties": {
    "tipoComprobante": { "enum": ["31","32",...] },
    "formato":         { "enum": ["ECF","RFCE"] },
    "payload":         { "type": "object", "description": "Payload flexible del comprobante. Se valida dinámicamente por tipo." }
  },
  "required": ["tipoComprobante", "payload"]
}
```

First test attempt with the flat DTO that `mapToEcfApiDto()` returns:
```
HTTP 400 — {"message":["property items should not exist","property rncComprador should not exist",...,"payload must be an object"], ...}
```

After wrapping `{ tipoComprobante, formato?, payload: { …rest } }`, every payload was accepted. **All five test cases below were run with the manually-wrapped variant.** Without this fix the dev server's `/api/ecf/emitir` cannot emit a single comprobante.

### Fix needed
**Files:** `lib/ecf-api/emision-mapper.ts:321-579` (the `mapToEcfApiDto` return), and consumers in `app/api/ecf/emitir/route.ts:261` and `app/api/ecf/preview/route.ts` (if it uses the same DTO).

**Proposed change** (smallest blast radius — patch the mapper to return the wrapped shape):
```ts
// in each return branch of mapToEcfApiDto, replace
return { tipo, esRfce, dto: { tipoComprobante: tipo, formato?, …rest } };

// with
const { tipoComprobante, formato, ...rest } = inner;   // pull header keys out
return {
  tipo,
  esRfce,
  dto: {
    tipoComprobante,
    ...(formato ? { formato } : {}),
    payload: rest,
  },
};
```
Or, simpler — wrap at the call site (`route.ts:261`):
```ts
const { tipoComprobante, formato, ...payload } = ecfApiDto as Record<string, unknown>;
const body = { tipoComprobante, ...(formato ? { formato } : {}), payload };
resultado = await emision.emitirUnified(codigoPublico, body, habilitacionHeaders);
```

Also recommend: refresh `lib/ecf-api/client.ts:298` JSDoc to document the wrapper shape.


**DGII:** `RECHAZADO`, cod 156: "El campo IndicadorNotaCredito del área IdDoc no es válido".

**Retest with `indicadorNotaCredito: 1`** (E340000000002 / id `cmp3jsw80005dpm01d7kenfnv`): DGII still rejects, this time cod 181 "TipoIngresos no es válido" — but XML inspection shows no `<TipoIngresos>` element is emitted for tipo 34 (mapper correctly omits it). Cod 181 in this case is DGII's response to the entire e-CF being invalid for other reasons (likely the synthetic NCFModificado, same as tipo 33).

**Retest with the field omitted entirely:** ecf-api validator rejects with `400 "Campo requerido faltante: indicadorNotaCredito"` — so the field IS required by ecf-api.

**Conclusion on tipo 34:** Payload is structurally accepted by ecf-api. DGII cod 156 for `value=0` is a DGII XSD quirk (DGII appears to expect this element only when value=1, contradicting ecf-api's requirement). **This is an upstream contract mismatch between ecf-api and DGII XSD** — not an emitedo bug. Flag for ecf-api maintainers.

**Verdict: PASS** structurally; **upstream issue** to flag.

## I. Fixes Needed

### 1. CRITICAL — wrap DTO in `payload`
- **Files:** `lib/ecf-api/emision-mapper.ts` (all return branches, lines 338-578) **or** `app/api/ecf/emitir/route.ts:261`.
- **Change:** as described in section B above. Choose the route.ts site for smallest blast radius (one change covers all tipos).
- **Impact:** without this, **zero** emissions can succeed via dev server `/api/ecf/emitir`.

### 2. NICE TO HAVE — confirm `X-Dgii-Ambiente` plumbing
- `app/api/ecf/emitir/route.ts:244-247` only sets the header when `skipRangeValidation === true`. For normal emissions with registered ranges, ecf-api falls back to the contribuyente's stored ambiente (`TesteCF` for us). This worked, but worth a smoke test once tipo-by-tipo ranges are in place across CerteCF.

### 3. UPSTREAM (not our bug) — tipo 34 `IndicadorNotaCredito=0` rejection
- DGII cod 156 rejects `<IndicadorNotaCredito>0</IndicadorNotaCredito>` while ecf-api requires the field to be present. Flag to ecf-api maintainers — either omit the element when value=0 in the XML signer, or document the workaround. Not actionable in emitedo until upstream changes.

### 4. URL/AMBIENTE mismatch with prompt
- Prompt said `ECF_API_URL=https://ecf-api.yisraeltech.com/v1` and ambiente `CerteCF`. `.env` actually has `https://ecf-api.yisraelschool.com/v1` and the contribuyente is on `TesteCF`. Worth confirming with the user which is intended before any production switchover.
